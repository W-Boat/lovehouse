# 区域与物件文案替换验收

本批新增真实可应用字段：scene.<zone>.name/caption 与 item.<zone>.<item-id>.name/action。区域key、物件id、门户目标、坐标、寻路、座位身份均不变。重复出现在不同区域的id使用zone隔离，不会互相覆盖。当前导出共1307个合法且唯一ID，其中区域字段36个、物件字段376个。

导出器先加载apply-copy，所以已经填写在personal.texts里的值会保留。动作标签留空维持系统默认，不能靠改“坐”字创造新座位。世界地图原有按动作文字识别休息类别只影响显示图标，不控制坐下动作；主代理需改为座位语义分类以适配自定义标签。

文案.md已重新导出并复制outputs。使用tools/apply_copy.py 文案.md 后正常构建，自动重建字库，不要求修改业务源码。

3项离线测试通过：改变显示文字不影响物件结构/导航；全部场景与物件字段有对应导出slot；直接读取实际Python导入器regex解析全部文案，确认ID唯一合法、Unicode和多行值JSON往返一致。TypeScript通过。测试不会将改名后的动作当新玩法。

## 固定系统字与答案配置

index.html首次加载遮罩/页面标题是通用系统文字，当前不作为私人替换项；用户不需要修改这些源码才能填写生日、称呼、信件、照片和歌曲。若未来需要主题自定义，可另扩稳定ID，不能将现在的静态标题伪称已经动态可配置。

小游戏便签排序答案依旧是受约束的关卡数据；notes线索更改必须匹配答案顺序。它们与个人日常便签note.<index>不是同一配置。不能通过任意文案替换承诺任意新谜题可玩。

本批没有本地服务/浏览器/EXE验证。自定义长场景名、长物件名的布局和地图图标仍需CI或实际设备截图；文案可导入不代表所有长文本界面已视觉通过。
