# 联机与桃源乡追加要求

依据用户在 2026-11-13 的明确追加，原单机范围扩展为真正双人联机；原 41 项及四季、日历、圆形小地图仍保留，不能用本追加替代原验收。

## 必须交付

1. 两个真实客户端加入同一私密房间。主玩家与副玩家各控制自己的角色；远端角色通过网络同步，不能继续由本地 AI 假扮。角色方向、外观、位置、区域及动作相符。
2. 主玩家邀请跟随，副玩家明确接受或拒绝；双方可停止跟随。狭窄通道遵循原寻路，跨区域与断线均取消过期动作，不允许闪现追赶。
3. 可设置服务器地址和默认服务器。用户点击连接才发起通信；显示连接中、已连接、重连及失败，未配置可用服务时不能假装在线。HTTPS 网页使用 WSS。
4. 聊天、共同书写、共同小游戏与精灵宠物。书写遇到版本冲突保留本地草稿；小游戏需真正共享同一局与输入结果，只有事件广播接口不算玩法完成。宠物需可见动画与状态同步，只有选择菜单不算完成。
5. 接入用户指定的 setube/taoyuan。主空间房间中央提供可见传送门，桃源乡内保留返回主空间入口；双方身份和房间贯通。保留上游许可与来源，独立存档命名，不能用普通外链冒充接入。
6. 保留单机游玩、原存档和私人文案。退出联机、断线及桃源乡返回均可恢复合理状态。

## 并行分工和依赖

- 服务端与协议：私密双席、重连身份、权限、文档版本、游戏事件、宠物状态、消息边界和限流。纯状态机可离线测试，真实 Socket 测试只在 CI 运行。
- 客户端传输：地址校验、显式连接、重连取消与旧消息隔离；不自动重放离线动作。
- 联机界面：服务器、房间、聊天、书写、邀请和宠物；网络消息通过安全文本节点显示。
- 场景整合：主副玩家控制权、远端插值、动画与外观、跟随、区域可见性和断线恢复。
- 桃源乡：先核实上游代码、许可与存储，再实现可维护的构建和联机桥接。
- 最终集成：共同小游戏实际规则、宠物动画、双客户端浏览器测试、网页/Windows 构建与同提交交付。

## 验收门槛

不能把服务端状态机通过当作真实联机通过。CI 需启动服务并用两个独立浏览器上下文验证创建/加入、各自移动、邀请与取消、聊天、冲突恢复、共同游戏、重连、传送门和返回；第三客户端应无法占用已有双席。测试失败不得更新最终交付为通过。

不在本地启动服务器、网页预览或客户端。GitHub Actions 内运行测试服务不等于公开部署；没有得到明确指令，不发布公网默认服务器。
