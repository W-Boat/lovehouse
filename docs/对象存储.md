# 对象存储

发布服务支持 S3 兼容储存桶，用于 Android APK、Windows ZIP、后台或 CLI 上传的图片、音视频、HTML、JSON、ZIP，以及签名增量更新文件。发布清单、版本历史、账号与开放规则等仍保存在服务器，需要照常备份。

在发布服务器的受保护服务环境文件中配置：

~~~dotenv
LOVEHOUSE_S3_BUCKET=your-private-bucket
LOVEHOUSE_S3_REGION=auto
LOVEHOUSE_S3_ENDPOINT=https://your-s3-endpoint
LOVEHOUSE_S3_PREFIX=lovehouse
LOVEHOUSE_S3_PATH_STYLE=true
LOVEHOUSE_S3_ACCESS_KEY_ID=
LOVEHOUSE_S3_SECRET_ACCESS_KEY=
# 短期凭据需要同时设置 LOVEHOUSE_S3_SESSION_TOKEN
~~~

AWS S3 使用实际区域，省略自定义端点，通常也省略 path-style。Cloudflare R2 使用 S3 API 端点和区域 auto。其他兼容服务采用各自的区域、端点和寻址要求。凭据只授权该桶对应前缀的对象读取、写入和删除。部分 S3 服务需要允许限定前缀的 ListBucket，以便对不存在的对象正确返回 404。

在发布服务目录安装生产依赖（本仓库的 package.json 和 package-lock.json，执行 npm ci --omit=dev），再重启服务。后台状态横幅和 CLI 的 storage 命令可以查看存储模式。未设置 LOVEHOUSE_S3_BUCKET 时继续使用本地磁盘。

默认阈值为 10 MB（10,000,000 字节）。大于阈值的文件上传和读取首选储存桶，服务器磁盘备用；等于或小于阈值首选服务器磁盘，储存桶备用。后台「发布与资源 → 存储规则」可以调整阈值和四组首选、备用位置。备用可留空。修改后立即影响后续传输，已有文件不会自动迁移。下载在首选位置缺失或打开失败时尝试备用；若数据传到一半中断，客户端重新请求。建议迁移期间保留两个位置的读取路径。

CLI 执行 `storage` 查看模式和规则，执行 `storage-set rules.json` 保存。配置文件结构如下：

~~~json
{
  "thresholdBytes": 10000000,
  "small": {"upload": ["local", "s3"], "download": ["local", "s3"]},
  "large": {"upload": ["s3", "local"], "download": ["s3", "local"]}
}
~~~

旧文件可以逐步迁移。保留原文件名，将 content.json.assets 下的有效素材文件放在 media/，安装包哈希文件放在 packages/，更新 blobs 放在 android-update/blobs/，均位于配置前缀下。先核对对象大小和哈希，再清理本地副本。切换回本地模式前，需要把仅存于桶的对象同步回原目录。

客户端继续通过原来的发布地址下载。服务代理私有桶的文件并保留安装包 Range、素材 CSP 和原有签名校验。仅配置桶不会解决 GitHub runner 连不到发布服务器的网络问题。
