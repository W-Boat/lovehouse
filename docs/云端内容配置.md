# 云端内容配置

构建网页、Windows 或 Android 时，在运行 Vite 的环境设置 `LOVEHOUSE_CONTENT_SERVER`，值为 HTTPS 服务基地址。正式包默认使用 `https://server.080726.xyz/lovehouse/`，也可在构建时覆盖。客户端启动时向该地址请求 `content.json`，超时为 2.2 秒。同修订服务端返回 304，离线时客户端使用上次成功保存的配置。

Agent 可用 `node tools/cloud-content.mjs publish INPUT OUTPUT` 校验并原子生成快照。输入为 JSON 对象，`texts` 使用文案.md 中的稳定 ID，`portals` 为最多两条包含 `label` 和 HTTPS `url` 的记录。命令返回 JSON 修订号。用 `node tools/cloud-content.mjs serve SNAPSHOT` 运行只读接口，默认绑定 127.0.0.1:8789。也可把输出文件发布到 HTTPS 静态站点，静态站点需要配置 CORS 和条件请求才能省去重复传输。

该阶段覆盖文案、替换素材地址、唱片房歌单与两个 HTML 传送门槽位。浏览器在沙盒中打开配置的页面。场景定义、礼物规则、二进制资源差量更新、私密内容访问控制仍待接入。只读接口属于公开发布接口，私人内容应等访问控制完成后再接入。

## 发布唱片房歌单

在输入 JSON 中加入可选的 `musicRoom`，与 `texts`、`portals` 同级。修订号覆盖歌单。玩家可以在唱片房切换「跟随发布歌单」、自选歌单或内置离线唱片。原来已保存的自选配置继续使用。

```json
{
  "musicRoom": {
    "mode": "online",
    "server": "tencent",
    "type": "playlist",
    "id": "8668419170",
    "api": "https://music.zhheo.com/meting-api/?server=:server&type=:type&id=:id&r=:r"
  }
}
```

`server` 支持 `tencent`、`netease`、`kugou`，`type` 支持 `playlist`、`album`、`song`。也可用 `mode: "offline"` 配合 1–60 条 `localTracks`，每条填写 `name`、`artist`、`url`、`cover`、`lrc`。封面和歌词可以留空。资源可填 HTTPS 地址，或发行包内 `assets/`、`audio/`、`music/` 路径。离线会保留歌单配置，远程歌曲、封面和歌词需要网络。

## 发布礼物、回忆和演唱会素材

在发布输入中加入可选的 `media` 对象。它沿用 `content/personal.json` 的字段名，支持 `birthDateForMoon`（`YYYY-MM-DD`）、`moonImage`、`labubuImage`、`mysteryImage`、`concertAudio` 及最多 24 条 `memoryPhotos`。地址使用 HTTPS。省略字段会使用出厂值，空字符串或空照片列表会明确清除对应字段。

发布会校验格式并把媒体配置计入修订号。客户端启动只取配置，打开礼物、放映电影或进入火星演唱会时才读取素材。离线可复用地址配置，未缓存的网络媒体仍依赖网络。礼物图片无法打开时保留内置图。此发布接口公开，请只放可公开访问的素材。

## 为现有场景添加互动点

`interactions` 接收最多 100 项，每项配置 `id`、`zone`、`x`、`y`、`point`、`name`、`action`、`response`。`id` 必须以 `cloud-` 开头，后缀用小写字母和短横线。`x`、`y` 是场景内图标坐标，`point` 是玩家走近时的落脚点。使用场景原始坐标（640 × 426），例如摩天轮站台附近可用 `zone: "ferris"` 和 `point: [320,370]`。客户端会忽略未知场景、重复项或无法从入口走到的点。点击后用场景内提示显示 `response`，并记录到当前存档。删掉条目并发布即可移除该互动。

互动点可选填 `game`，值为现有的礼物小游戏 ID，例如 `"game": "moon"`。点击后在场景内开启练习，完成或跳过会显示该互动的 `response`。练习成绩独立于礼物进度，首次拆礼物时仍按原规则游玩。未知小游戏 ID 会在发布时被拒绝。

互动点也可填 `url` 打开 HTTPS 网页。网页嵌入小屋内的隔离窗口，关闭后回到原场景。`url` 和 `game` 二选一；目标网站需允许被 iframe 嵌入。

## 发布新增场景

`scenes` 最多 12 项。每项填写 `id`（`cloud-` 加小写字母）、`parent`（内置场景 ID）、`name`、`caption`、`background`（HTTPS 背景图）、`entrance`（父场景入口坐标）、`spawn`（到达点）、`exit`（返回点）和 `floor`（由左上、右下两个坐标确定的可走矩形）。使用 640 × 426 场景坐标。条目会生成双向入口并出现在世界地图。`interactions` 可引用新增场景的 ID。新场景目前用于单人探索；配置可离线复用。支持 Cache Storage 的客户端会保留最多 24 张已成功加载的背景；同一地址直接复用，换图时发布新 URL。背景服务器需允许客户端跨域读取（CORS），图片支持 WebP、PNG、JPEG、AVIF，单张上限 4 MiB，宽高各不超过 4096 像素。

## 注入独立编写的小游戏

互动点可配置 `"gameUrl": "https://games.example.com/my-game/index.html"`，指向独立发布的 HTML、JavaScript、CSS 游戏。小屋在场景内用隔离 iframe 加载游戏，允许游戏脚本执行。玩家可以随时关闭并回到原场景。新版只需发布配置和游戏文件。模块脚本或跨域资源请按 iframe 的跨域要求配置；也可用普通脚本或单 HTML 打包。小游戏需要允许被 iframe 嵌入，并自行处理触摸和窗口缩放。

`gameUrl`、`game`、`url` 最多填一个。独立游戏拥有自己的运行环境，暂未接入礼物进度、存档或联机协议。

若要把独立小游戏绑定到礼物，在发布配置顶层填 `"giftGames": {"moon": "https://games.example.com/moon/index.html"}`。第一次拆礼物和礼物详情里的重玩按钮均使用该入口。游戏完成时调用 `window.parent.postMessage({type:"lovehouse:minigame-complete"}, "*")`。小屋只接收当前游戏窗口的消息，按通关记录；玩家也可以主动跳过，或点「玩内置版」走相同的礼物流程。直接关闭游戏不会发放礼物。

## 发布后台与 Agent

后台单独构建，不进入游戏客户端资源包。执行 `npm --prefix admin ci` 和 `npm --prefix admin run build`，然后在部署环境中设定 `LOVEHOUSE_ADMIN_TOKEN`，运行 `node tools/cloud-content.mjs serve /path/to/content.json`。在 HTTPS 反向代理上访问同站的 `/admin/`。服务器默认监听 127.0.0.1:8789，反向代理或容器可通过 `HOST`、`PORT` 调整。请将令牌放在服务端环境变量中。发布结果由 `/content.json` 公开提供。

Agent 可以运行 `node tools/cloud-content.mjs check INPUT` 做离线校验，或运行 `publish INPUT OUTPUT` 生成文件。两个命令的成功输出包含 JSON 修订号，错误以 JSON 输出到 stderr 并返回非零退出码。也可以发送 `Authorization: Bearer <token>` 调用发布服务。

| 请求 | 结果 |
| --- | --- |
| `GET /admin/api/snapshot` | 当前发布配置；尚未发布时为 `{}` |
| `POST /admin/api/check` | 校验请求中的 JSON 配置，成功返回 `{"revision":"…"}`，无写入 |
| `POST /admin/api/publish` | 校验并原子替换配置，成功返回 `{"revision":"…"}` |

POST 请求使用 `Content-Type: application/json`。发布时可附 `If-Match: "<revision>"`，首次发布用 `If-Match: ""`；若版本已被更新则返回 412。错误响应含 `error` 字段。管理员接口禁止跨站读取，客户端公开配置的版本协商保持原有 304 行为。并发管理应通过同一个服务进程进行，避免 CLI 和多个服务进程同时写同一个文件。

后台素材管理和自动上传分别见《发布后台操作手册》和《发布 Agent 操作手册》。
