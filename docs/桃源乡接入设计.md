## 实际接入

`tools/build_taoyuan.py` 解包 vendored 固定源，去除 Electron/Android 的构建步骤，仅安装网页依赖。注入 `tools/taoyuan-bridge.ts` 后构建至 `public/taoyuan`。根构建须先执行此工具，再 Vite build；不需要运行开发服务器。独立同源 iframe 载入随包分发的真实上游游戏，非外站链接。Vue 与 Phaser 样式、路由、音乐生命周期隔离。

主屋 world item `taoyuan-portal` 位置 320,282，接近点320,318；画面特效由场景控制器绘制。`src/taoyuan-portal.ts` 提供 `openTaoyuan({role,onExit,onMessage})`，返回 `receive(payload)` 与 `close()`。main 将位置与阻塞状态保存，关闭返回同位置；此最终桥接由主代理完成。

## 同房间协议

副玩家按钮操作发送 `{kind:'command',route,index,text}`，主玩家检查当前路由、按钮序号、文本及 disabled 再执行。主玩家用原生 SaveStore 保存后发送 `{kind:'state',save,route}`；副玩家原生 importSave/loadFromSlot 还原，同一份田庄不各自运行两份。主机操作后400ms防抖及每3秒同步。

服务器 `taoyuan-state` 仅主玩家、每秒2次、存档上限2MB；`taoyuan-action` 仅副玩家、每秒10次、明确路由和目标长度。最新田庄状态保存在 RoomSnapshot.taoyuan 以供短时重连；仍是内存房间，服务重启不提供云存档。iframe桥接检查 origin+source+channel，未暴露任意脚本执行。两个协议纯内存测试已通过，涵盖权限、超长数据、操作转发及重连。

## 尚须验证和扩展

真实上游本地构建仍在执行，CI双浏览器协作、触摸、退出恢复、音乐隔离未验证。副玩家目前可协作点击按钮；自由文本输入、下拉、滑杆未代理，不得宣称所有操作均支持双人。并发按钮列表变化时请求会被拒绝，依赖下一次权威快照恢复。主机窗体关闭时不再运行田庄；副玩家应显示等待状态。主机离开/重新进入以及共同存档和生日小屋导出整合须主代理完成。
