# 后台与下发功能深化计划

采用用户确认的 Vue 3 + Element Plus。现有线上基址为 https://server.080726.xyz/lovehouse/。保留现有游戏配置与存档兼容性。浏览器及实机验收继续延后，构建、离线测试及授权的服务器接口验证照常执行。

## 一、发布数据与回滚

发布和 CLI 共用格式校验，写入前保存修订快照。后台显示历史版本、发布时间、大小和当前状态，允许带当前版本条件回滚。并发修改返回冲突并保留草稿。历史版本引用的素材一并保护。验证首次发布、重复发布、回滚、冲突和写入失败后的当前文件。

## 二、Element Plus 主界面

使用清晰的导航、页面工具栏和状态提示。文案、场景、互动、传送门、歌单、替换素材和礼物小游戏提供可操作的表单，保留 JSON 模式。编辑、导入和切换页面不得丢失未发布内容。草稿本机恢复不包含发布令牌。发布前显示修改摘要，防止读线上配置时静默覆盖草稿。

## 三、素材库

支持搜索、类型筛选、分页、图片和音频预览、多文件顺序上传、进度、失败信息和复制链接。删除需检查当前与历史引用。保持素材内容哈希去重。自动上传 CLI 使用相同鉴权与校验。验证大文件、无效内容、重复文件和被引用素材。

## 四、下发一致性

客户端验证修订号与内容哈希，失败使用上次成功配置。保持启动超时进入游戏，缓存按服务器分开。场景、互动、歌单、媒体、礼物游戏和传送门都经过同一发布契约核对。远程资源按需读取与离线回退继续覆盖原有数据。记录完整配置注入、同修订免更新、离线和损坏数据的结果。

## 五、人和 Agent 的完整操作路径

更新人类操作手册与 Agent 手册，覆盖上传、导入、校验、发布、历史、回滚、冲突合并和错误码。提供与实际 API 一致的命令和部署路径。后台可导出完整草稿，Agent 可生成同一格式并提交。

## 六、构建与远程交付

先检查当前工作区差异和测试，再构建后台与游戏。部署到现有独立服务，验证 HTTPS 页面、鉴权、上传和版本接口。发布真实配置前保留当前线上内容。更新构建产物和需求审计，明确已实现、未实现与待视觉验收项。客户端更新由 GitHub Actions 构建。

当前实施从一至四并行开始，五与六在实现后同步完成。整份计划仍包括 Windows 差量更新、云端联机与私密内容访问控制等既有待办，它们继续记录于总审计。

## 完整后台功能与 10 个并行任务

目标为可日常维护的发布后台，所有既有下发类型都有表单、校验、导入导出与错误反馈。采用共享 API 及统一修订号，人和 Agent 均可操作。3 个子代理并行运行，后续任务按依赖补位。

|任务|交付|范围与验收|
|---|---|---|
|1 操作契约与文档|人类、Agent 操作手册|核对线上路径、令牌、素材、历史、回滚、冲突与草稿|
|2 歌单完整表单|MusicForm.vue|平台、ID、类型、API、逐曲音源封面歌词，增删与默认恢复|
|3 替换素材表单|MediaForm.vue|生日日期、礼物图片、演出音源、回忆照片与预览|
|4 草稿与变更摘要|独立草稿模型|本机恢复、非法 JSON 保留、切换不丢失、导入防覆盖、逐分区差异|
|5 发布历史界面|History.vue|历史搜索、当前标记、版本详情、导入草稿、带修订条件回滚|
|6 场景编辑提升|场景预览与编辑|背景预览、点位和行走范围可视化、尺寸和连接关系反馈|
|7 互动与游戏管理|互动表单提升|场景选择、行为互斥、内置游戏与独立游戏绑定、坐标可读性|
|8 素材引用与生命周期|引用查询与界面|当前及历史引用定位、被使用提示、去重、批量上传失败重试|
|9 Agent 发布能力|CLI check/upload/history/pull/push|机器可读结果、If-Match 冲突、HTTPS 与路径前缀一致性|
|10 联调与交付|构建/测试/部署记录|共享校验、离线缓存、哈希完整性、线上鉴权与回滚验证，视觉实机延后|

扩展管理范围继续保留账号与私密内容访问控制、客户端配置状态、设置策略下发及独立游戏联机协议，按总计划追踪。当前不将公开内容接口当作私密内容存储。新增管理权限应与现有发布令牌兼容，并在开放私密内容前完成身份与读取授权。Windows 文件级更新仍列入总审计。

实施顺序为 1/2/3，随后 4/5/6，再 7/8/9，最后 10 汇总。根代理负责集成、运行状态与线上配置保护。
