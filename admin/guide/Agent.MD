# Lovehouse Agent.MD

所有接手 Lovehouse 开发或发布的 Agent 在执行前必须阅读本文件和 HANDOFF.md。若将技能包用于长期维护，把两份文件纳入项目的交接流程。仓库中另有作用域指令时一并阅读，明确的用户指令优先。

1. 用 `git status --short --branch` 和 `git rev-parse --short HEAD` 确认实际工作树。按任务选读 references/。CLI 以当前提交的 `tools/cloud-content.mjs` 为准。
2. 云端配置改动先拉取发布快照，保留无关字段，发布时带原修订号。遇到 HTTP 412 重新拉取并合并改动。发布前后各保留一个可复用的修订记录。
3. `.ENV` 只保存在本地。部署地址、发布令牌、SSH 信息从配置或密钥管理器读取。不要把真实凭据放进源码、ZIP、文档、截图、工具输出或交接记录。构建变量和管理员令牌分别管理。
4. 每个变更沿正常使用入口验证。仅改云内容时优先使用 CLI 校验。改前端、后台、服务端协议或打包时运行对应检查，区分构建成功、部署成功、下载页已切换和实机验证。
5. 交接前必须更新 HANDOFF.md。记录日期、提交、变更模块、运行命令及结果、Actions 链接、实际线上版本、待验证项和下一步。失败或中断也写入。并行 Agent 先报告文件及证据，再由主 Agent 合并交接。
